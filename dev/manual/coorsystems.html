Coordinate systems (symbolic) ​

See also

Theory: Curvilinear differential calculus · Classical coordinate systems · Spheroidal coordinates · Ellipsoidal coordinates

Manual: Coordinate systems (numerical) · Charts and coordinate conversions

Tutorials: Differential operators, symbolically · Christoffel symbols · Differential operators, numerically · Classical identities of the differential operators · The operators in the classical systems · The spheroid in spheroidal coordinates · Ellipsoidal coordinates

Differential operators on tensor fields, with exact symbolic derivatives. The mathematics — natural basis, Lamé coefficients, Christoffel symbols, the index placement of each operator — is on Curvilinear differential calculus.

Each curvilinear system is drawn, with its normalized basis and its surfaces of constant coordinate, in an interactive figure of its Theory page: Classical coordinate systems, Spheroidal coordinates, Ellipsoidal coordinates. A system that is not in the table is built from its position vector, see Custom systems below.

Load SymPyPythonCall for the default coordinates

Called without coordinates (coorsys_spherical()), a constructor names its coordinates with SymPy symbols, which needs using TensND, SymPyPythonCall. With Symbolics, pass the variables, coorsys_spherical(Tuple(@variables θ ϕ r)), or the type, coorsys_spherical(Val(Num)).

Ordering of the spherical coordinates

The spherical coordinates are ordered , not , so that    reproduces the canonical basis in the canonical order.

The operators ​

julia
using TensND, SymPyPythonCall

Polar = coorsys_polar()
r, θ = get_coords(Polar)
𝐞ʳ, 𝐞ᶿ = unitvec(Polar)
@set_coorsys Polar

laplacian(SymFunction("f", real = true)(r, θ))

  

@set_coorsys installs a default system so the operators take one argument; without it, pass the system explicitly, laplacian(f, Polar).

CallDoes
@set_coorsysCS / set_coorsys!(CS)make CS the default
default_coorsys()the current default (throws if none)
unset_coorsys!()forget it

∂ is deliberately not affected by the default

∂(t, x) always means the plain derivative of t with respect to the symbol x; for the covariant derivative pass the chart explicitly, ∂(t, x, CS).

Defining a method for ∂(t, x) in the TensND module would be more specific than the plain-derivative fallback, so that the same call would silently change meaning, and since both CoordinateSystem and Submanifold differentiate a position vector while being built, constructing any new chart after a @set_coorsys would fail. The default is therefore simply stored, and the single-argument operator methods are defined once.

Custom systems ​

A system that is not predefined is built from its position vector, by one of the routes of Curvilinear differential calculus.

From the position vector alone ​

julia
CoordinateSystem(OM, coords, tmp_coords = (), params = ();
              rules = Dict(), tmp_var = Dict(), to_coords = Dict())

The position vector and the coordinate symbols suffice: the natural basis, the Lamé coefficients, the normalized basis and the Christoffel symbols are derived. The parabolic coordinates of the plane,     :

julia
using TensND, SymPyPythonCall

x, y = symbols("x y", real = true)
OM = Tens([(x^2 - y^2) / 2, x * y])
Parabolic = CoordinateSystem(OM, (x, y))
lame_coefficients(Parabolic)
(sqrt(x^2 + y^2), sqrt(x^2 + y^2))

From the position vector, the basis and the Lamé coefficients ​

julia
CoordinateSystem(OM, coords, ℬ, χᵢ, tmp_coords = (), params = (); kwargs...)

When the unit vectors and the Lamé coefficients are known in closed form, passing them spares the computer algebra system the work of finding them, and keeps them in the form they were written in. Only the Christoffel symbols are computed. Here   and   , both of norm  :

julia
χ = sqrt(x^2 + y^2)
ℬ = RotatedBasis([x/χ -y/χ; y/χ x/χ])
Parabolic = CoordinateSystem(OM, (x, y), ℬ, (χ, χ))
f = SymFunction("f", real = true)(x, y)
tsimplify(laplacian(f, Parabolic))

Every predefined system is built this way.

From a function ​

When no closed form is wanted, the position vector is given as a function of the coordinates and the geometry is evaluated at each point by automatic differentiation: see Numerical coordinate systems.

Taming symbolic expressions ​

Non-trivial charts produce metric expressions SymPy will not reduce unaided, and the Christoffel symbols become unusable nested radicals. Four optional arguments control this:

ArgumentRole
tmp_coordsauxiliary symbols standing for compound expressions
paramsconstants appearing in
tmp_varsubstitutions replacing expressions by those symbols
to_coordshow to eliminate them again before differentiating
rulesrewrite rules applied after each simplification

The prolate spheroidal system is the standard illustration: coorsys_spheroidal names   and  , and writes the position vector with them.

julia
Spheroidal = coorsys_spheroidal()
position_vector(Spheroidal)

julia
lame_coefficients(Spheroidal)
(c*sqrt(1 - p^2)*sqrt(q^2 - 1), c*sqrt(-p^2 + q^2)/sqrt(1 - p^2), c*sqrt(-p^2 + q^2)/sqrt(q^2 - 1))
julia
simplify(laplacian(position_vector(Spheroidal)[1]^2, Spheroidal))

The ellipsoidal system names its six square roots in the same way:

julia
Ellipsoidal = coorsys_ellipsoidal()
position_vector(Ellipsoidal)

Symbolic or numerical? ​

For pointwise evaluation, sweeps and gradients, use the pointwise CoordinateSystem instead — same operator names, derivatives by automatic differentiation. See Numerical coordinate systems.
