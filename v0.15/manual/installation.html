Installation ​

TensND is registered in the Julia General registry.

julia
julia> import Pkg; Pkg.add("TensND")

or, from the Pkg REPL mode (]):

julia
pkg> add TensND

Symbolic backends ​

What to load for symbolic computations

to work withaddload
SymPy symbols (Sym: symbols, @syms, SymFunction), and the coordinate systems called without coordinates (coorsys_spherical(), init_cartesian(), …)pkg> add SymPyPythonCallusing TensND, SymPyPythonCall
Symbolics variables (Num: @variables)pkg> add Symbolicsusing TensND, Symbolics
numbers and derivatives onlynothingusing TensND

Symbolics is a dependency of TensND; SymPyPythonCall is not: what calls Python lives in an extension that loading SymPyPythonCall activates, so that using TensND alone does not load Python. Called without coordinates while SymPyPythonCall is not loaded, a coordinate system says so in its error message.

SymPyPythonCall reaches Python through PythonCall, and CondaPkg installs the Python module sympy on first use, in an environment of its own: no Python needs to be set up beforehand. To use a Python of your own instead (one that has sympy), set

julia
ENV["JULIA_CONDAPKG_BACKEND"] = "Null"
ENV["JULIA_PYTHONCALL_EXE"] = "/path/to/python"

before loading SymPyPythonCall.

Code written for SymPy.jl changes using SymPy into using SymPyPythonCall; the symbols of the two packages are different types.

See Symbolic and numeric for how the four scalar worlds — Float64, ForwardDiff.Dual, Sym and Num — relate.

Checking the installation ​

julia
using TensND

Spherical = coorsys_spherical()
θ, ϕ, r = get_coords(Spherical)
𝐞ᶿ, 𝐞ᵠ, 𝐞ʳ = unitvec(Spherical)
@set_coorsys Spherical

divergence(𝐞ʳ)          # 2/r
laplacian(1 / r)   # 0

If those two return 2/r and 0, the symbolic stack is working.
